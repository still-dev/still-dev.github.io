1 DATA INGESTION

영상 인입 및 비식별화

병원에서 찍은 영상이 개인정보가 제거된 채로 안전하게 클라우드에 도착하는 과정입니다.

📷

촬영 장비 (CT / MRI / X-Ray)

DICOM 형식 출력

환자가 CT나 MRI를 찍으면 DICOM 파일이 생성됩니다. DICOM은 의료 영상 전용 파일 형식입니다 (사진의 JPG처럼 의료계의 표준 포맷).

비유: 휴대폰으로 사진 찍으면 JPG가 생기듯, CT 찍으면 DICOM이 생깁니다.
🏥

PACS (병원 영상 저장소)

Picture Archiving and Communication System

촬영된 DICOM 파일이 병원 내부 서버인 PACS에 자동 저장됩니다. 의사들이 모니터에서 영상을 보는 시스템이 바로 이것입니다.

비유: 병원 전용 구글 포토 같은 것. 모든 촬영 영상이 여기에 모입니다.
🔒

비식별화 모듈 (De-identification)

HIPAA · GDPR 준수 · PHI 제거

DICOM 파일에는 환자 이름, 주민번호, 생년월일 등이 포함되어 있습니다. 클라우드로 전송하기 전에 이 개인정보를 모두 제거(마스킹)합니다.

비유: 시험지 제출 전에 이름 가리는 것. 누구의 데이터인지 알 수 없게 만듭니다.
☁️

AWS S3 버킷 (클라우드 저장소)

Amazon S3 · 무제한 용량 · 암호화 전송

비식별화된 DICOM 파일이 AWS S3에 업로드됩니다. S3는 용량 제한 없이 파일을 저장할 수 있는 클라우드 저장소입니다.

비유: 무제한 용량의 구글 드라이브. 수천 장의 CT 영상도 거뜬히 저장합니다.
⚡

AWS Lambda 트리거 (자동 감지)

Event-Driven · Serverless · EventBridge 연동

S3에 새 파일이 올라오는 즉시, Lambda가 이를 자동으로 감지하고 다음 분석 단계(Nextflow)를 깨웁니다. 사람이 직접 시작 버튼을 누를 필요가 없습니다.

비유: "새 파일 왔어!" 하고 알려주는 알림봇. 24시간 대기하다가 파일 도착하면 바로 반응합니다.
2 PREPROCESSING

고속 병렬 전처리

AI가 영상을 읽기 전에 "보기 좋게 정리"하는 과정입니다. 사진 보정 앱처럼 생각하면 됩니다.

전처리 A

HU 윈도잉 (밝기 조절)

CT 영상의 밝기·대비를 조절해서 뼈/뇌/혈관이 각각 잘 보이게 만듭니다. 같은 CT라도 윈도잉에 따라 보이는 것이 다릅니다.

전처리 B

Skull Stripping (두개골 제거)

뇌 CT에서 뼈 부분을 삭제합니다. AI가 뇌 안쪽의 출혈·종양만 집중해서 볼 수 있게 배경을 지우는 것입니다.

전처리 C

슬라이스 선별 & 리사이징

CT 한 번에 수백 장이 나옵니다. 이 중 핵심 단면만 골라내고 AI 모델이 읽기 좋은 크기로 조절합니다.

전처리 D

Feature Extraction (특징 추출)

이미지를 AI가 이해하는 숫자 벡터(리스트)로 변환합니다. 이후 Bedrock이 텍스트와 함께 읽을 수 있는 형태가 됩니다.

🎯

Nextflow + AWS Batch

Nextflow (워크플로우 엔진) · AWS Batch (GPU 컴퓨트)

Nextflow는 "지휘자"입니다. 위의 4가지 전처리 작업을 수십 대의 GPU 컴퓨터(AWS Batch)에 동시에 시킵니다. 혼자 하면 30분 걸릴 일을 동시에 돌려서 2~3분 만에 끝냅니다.

비유: 식당 주방장(Nextflow)이 요리사 10명(GPU)에게 "너는 전채, 너는 메인, 너는 디저트" 하고 동시에 시키는 것. 1명이 하면 1시간, 10명이 하면 10분!
3 AI REASONING

맥락 수집 + 멀티모달 AI 추론

"사진만 보지 말고, 환자 차트도 같이 봐!" — 이것이 기존 AI와의 핵심 차이점입니다.

🧠

입력 A: 영상 분석 결과

PyTorch 3D CNN · Amazon SageMaker

전처리된 CT/MRI 영상을 3D CNN(3차원 합성곱 신경망)이 스캔합니다. "뇌 CT 42~45번 슬라이스에서 고밀도 음영(출혈 의심) 발견, 크기 약 3cm" 같은 1차 분석 결과가 나옵니다.

📋

입력 B: 환자 차트 (EMR 데이터)

AWS HealthLake · HL7 FHIR API

AI 에이전트가 스스로 병원의 전자의무기록(EMR) 시스템에 접속하여 환자의 혈압, 기저질환, 혈액검사 결과를 가져옵니다. "혈압 190/110mmHg, 고혈압 병력 있음"

비유: 의사가 CT 사진 옆에 환자 차트를 펼쳐놓는 것. AI도 똑같이 합니다.
🔗

멀티모달 종합 추론

Amazon Bedrock (Claude) · Cross-Attention

Bedrock이 두 정보를 동시에 보고 교차 검증합니다. "CT에서 출혈 의심 + 혈압 190/110 + 고혈압 병력 → 급성 뇌출혈 확률 99%". 이때 Cross-Attention이라는 기술로 "영상의 이 부분"과 "차트의 이 수치"를 연결짓습니다.

비유: 의사의 사고 과정 그 자체. 사진만 보면 "그림자인가?" 싶지만, 차트까지 보면 "아, 이건 출혈이야!"로 확신이 강해집니다.

출력값 3가지

긴급도 점수

0~100점. 점수가 높을수록 위급함. 예: 98/100

중증도 확률

해당 질환일 확률. 예: 0.95 (95%)

판단 근거 텍스트

AI가 왜 이 결론을 내렸는지 설명. 의사가 검증할 수 있도록.

4 TRIAGE

자율적 중증도 분류 (Triage)

AI의 점수에 따라 "지금 당장!" vs "순서대로" 경로가 자동으로 갈라지는 분기점입니다.

⚖️

AWS Step Functions (판단 로직)

Choice State · if/else 자동 분기

Step Functions는 "만약 점수 > 90이면 RED, 아니면 GREEN" 같은 조건 분기를 자동으로 처리합니다. 코딩의 if/else문을 클라우드에서 실행하는 것입니다.

비유: 응급실 접수 데스크에서 간호사가 "이 환자 먼저!" 하고 분류하는 것(Triage)을 AI가 자동으로 합니다.

RED (점수 > 90) — 긴급

  • Amazon SNS로 전문의 스마트폰에 즉시 푸시 알림
  • PACS 판독 모니터 최상단에 팝업
  • 수술 준비팀에 자동 연락
  • DynamoDB에 판단 근거 기록

GREEN (점수 ≤ 90) — 일반

  • 영상의학과 정기 판독 리스트에 등록
  • 순서대로 판독 대기
  • DynamoDB에 판단 근거 기록
5 AUTO-SCRIBING

소견서 자동 작성 + 의사 승인

AI가 초안을 쓰고, 의사가 최종 사인합니다. "인턴이 쓰고 교수가 서명"하는 것과 같습니다.

📝

소견서 초안 생성

Amazon Bedrock (Claude) + RAG (Knowledge Bases)

영상 소견, 환자 차트, Triage 결과를 모아서 Bedrock이 전문 소견서 초안을 작성합니다. 이때 RAG를 활용해 해당 병원의 표준 판독 양식, 의학 용어를 참조합니다.

비유: RAG = "참고서를 먼저 찾아보고 답하는 AI". 멋대로 쓰는 게 아니라 정해진 형식과 용어를 지킵니다.
🔄

FHIR 표준 변환

AWS HealthLake · DiagnosticReport 리소스

생성된 텍스트를 병원 EMR이 이해할 수 있는 FHIR 표준 형식으로 변환합니다. '판독 부위', '소견', '결론' 등이 데이터 필드별로 구분됩니다.

비유: 한국어로 쓴 편지를 공문서 양식에 맞게 바꾸는 것. 내용은 같지만 형식이 공식적으로 바뀝니다.
✅

전문의 최종 승인 (Human-in-the-Loop)

API Gateway · Lambda · EMR 연동

의사가 EMR 화면에서 AI의 초안을 확인합니다. 수정할 수도 있고, 승인 버튼을 누르면 정식 의무기록으로 저장됩니다.

비유: AI는 인턴, 의사는 교수. 인턴이 쓴 보고서를 교수가 빨간펜으로 고치고 서명합니다.
🔁

피드백 루프 (MLOps)

S3 · SageMaker · 지속적 학습

의사가 수정한 내용이 다시 SageMaker로 피드백됩니다. AI가 다음에 더 잘 쓸 수 있도록 지속적으로 학습합니다. 이것이 MLOps(AI 운영)입니다.

비유: 교수가 빨간펜으로 고쳐준 걸 인턴이 복습해서 다음에 더 잘 쓰게 되는 것.

각 병원의 데이터는 밖으로 나가지 않습니다. 학습된 "지능(가중치)"만 모아서 하나의 통합 모델을 만듭니다.

Hospital C

외상 특화 병원

외상 영상 데이터로 로컬 학습 → LoRA 어댑터 (~50MB) 추출 → 암호화하여 중앙 서버로 전송

🧩

LoRA (Low-Rank Adaptation)

PEFT · QLoRA · SageMaker Training Jobs

모델 전체(수십GB)를 보내는 게 아니라 핵심 변경분만 담긴 작은 어댑터(~50MB)를 추출합니다.

비유: 레고 블록 전체를 보내는 게 아니라, 새로 끼운 블록 몇 개만 보내는 것. 훨씬 가볍고 빠릅니다.
🛡️

보안 전송 (Differential Privacy)

차분 프라이버시 · AWS Nitro Enclaves · 암호화

어댑터에 노이즈(잡음)를 섞어서 역추적으로 원본 데이터를 알아낼 수 없게 만듭니다.

비유: 시험 평균 점수는 공개하되, 누가 몇 점인지는 절대 알 수 없게 하는 것.
⚗️

중앙 합산 (FedAvg / FedProx)

AWS Lambda · Step Functions · 서버리스 합산

각 병원의 어댑터를 합쳐서 글로벌 모델을 만듭니다. FedAvg는 데이터량에 비례한 가중 평균, FedProx는 데이터 분포가 다를 때(Non-IID) 성능을 보정합니다.

비유: 3명의 요리사가 각자 레시피를 개발한 뒤, 좋은 부분만 모아 "최고의 레시피"를 만드는 것.

D DEVOPS & MONITORING

DevOps 인프라

코드 배포 자동화와 시스템 모니터링을 담당합니다.

🚀

CI/CD 파이프라인

GitHub Actions / Jenkins · Docker · Kubernetes (EKS)

코드를 Git에 푸시하면 → 자동 테스트 → Docker 이미지 빌드 → Kubernetes에 자동 배포. 사람이 서버에 접속해서 수동으로 배포할 필요가 없습니다.

비유: 편의점 발주 시스템처럼, 재고(코드)가 바뀌면 자동으로 진열(배포)까지 끝나는 것.
📦

컨테이너 오케스트레이션

Docker · Kubernetes (Amazon EKS)

각 서비스(AI 추론, Backend, 전처리)를 독립된 컨테이너(Docker)로 포장합니다. Kubernetes가 이 컨테이너들을 관리·스케일링합니다.

비유: Docker = 택배 상자 (어디서든 똑같이 작동). Kubernetes = 물류센터 관리자 (상자들을 어디에 배치할지 결정).
📊

모니터링

Prometheus + Grafana · ELK Stack

Prometheus가 서버 상태(CPU, GPU, 메모리)를 수집하고 Grafana가 대시보드로 시각화합니다. ELK Stack은 에러 로그를 수집·분석합니다.

비유: 자동차 계기판. 속도(CPU 사용률), 연료(메모리), 엔진 경고등(에러 로그)을 한눈에 보여줍니다.

민감도 (Sensitivity) 란?

실제 환자 중 AI가 "환자야!"라고 맞힌 비율. 놓치면 안 되는 상황에서 중요. 90%면 100명 중 90명을 잡아냄.

특이도 (Specificity) 란?

정상인 중 AI가 "정상이야!"라고 맞힌 비율. 오경보를 줄이는 데 중요. 90%면 헛경보 10%.

알람 피로도 (Alert Fatigue)

너무 자주 울리면 의사가 알람을 무시하게 됩니다. 특이도를 높여 오경보를 줄이는 것이 핵심.

EASY EXPLANATION

이 데이터셋이 뭔가요?

흉부 X-Ray란?

흉부 X-Ray는 가슴 부위를 X선으로 촬영한 사진입니다. 병원에서 감기가 심하거나 기침이 오래 갈 때 "가슴 사진 한번 찍어봅시다"라고 하는 바로 그 검사입니다. 이 사진에는 폐, 심장, 갈비뼈 등이 보입니다.

비유: 몸 속을 들여다보는 투시경. 폐에 이상이 있으면 하얀 그림자(음영)가 나타납니다.

COVID-19와 흉부 X-Ray의 관계

COVID-19에 감염되면 폐에 염증이 생깁니다. 이 염증은 X-Ray에서 하얀 얼룩(간유리 음영, Ground-Glass Opacity)으로 나타납니다. 정상 폐는 까맣게 보이는데, 감염된 폐는 뿌옇게 흐려지는 것입니다.

비유: 맑은 유리창(정상 폐)에 김이 서리는 것(COVID 폐렴). 김이 서릴수록 심하다는 뜻입니다.

이 데이터셋은 무엇을 하려는 건가요?

약 8만5천 장의 흉부 X-Ray 사진에 "이 사진은 COVID 양성", "이 사진은 COVID 음성"이라는 정답 라벨이 붙어 있습니다. AI에게 이 사진들을 보여주면서 "양성 사진은 이렇게 생겼고, 음성 사진은 이렇게 생겼어"라고 가르치는 것입니다.

비유: 시험 문제집에 정답지가 같이 있는 것. AI는 문제(X-Ray 사진)를 풀고, 정답(양성/음성)과 비교하며 학습합니다.
CLASSES

2가지 분류 클래스

positive COVID-19 양성

흉부 X-Ray에서 COVID-19 감염 소견이 확인된 이미지. 간유리 음영(GGO), 폐경화(consolidation) 등의 패턴이 나타납니다. 주로 양쪽 폐의 하부/외측부에 분포합니다.

ANALYSIS GUIDE

개별 분석 시 중점 사항

이 데이터셋을 담당하는 팀원이 통합 전에 반드시 확인하고 도출해야 할 소견들입니다.

1단계: 데이터 품질 점검 (EDA)

  • 이미지 해상도 분포 확인 — 모든 이미지가 같은 크기인지, 리사이징이 필요한지
  • 라벨 파일과 실제 이미지 파일이 1:1 매칭되는지 검증 (누락/불일치 확인)
  • 출처(cohen, ricord 등)별 이미지 특성 차이 분석 — 밝기, 대비, 해상도가 출처마다 다를 수 있음
  • 같은 환자ID로 중복 이미지가 있는지 확인 (data leakage 방지)
  • Train/Test/Val에 같은 환자가 겹치지 않는지 확인 (patient-level split 검증)

2단계: 전처리 파이프라인 설계

  • 이미지 정규화: 픽셀값을 0~1 또는 -1~1로 스케일링
  • 리사이징: 모델 입력 크기에 맞춰 통일 (예: 224x224, 512x512)
  • 데이터 증강(Augmentation): 좌우반전, 회전, 밝기 변경으로 학습 데이터 확장
  • CLAHE 적용: 흉부 X-Ray의 대비를 향상시키는 히스토그램 균등화 기법
  • 출처별 이미지 특성 차이를 줄이기 위한 도메인 정규화 검토

3단계: 모델 학습 및 도출할 핵심 지표

  • Sensitivity(민감도/재현율) — 실제 양성 중 AI가 양성으로 맞힌 비율. 목표: 90% 이상
  • Specificity(특이도) — 실제 음성 중 AI가 음성으로 맞힌 비율. 목표: 90% 이상
  • AUROC (Area Under ROC Curve) — 분류 성능의 종합 지표. 1에 가까울수록 좋음
  • F1-Score — 정밀도와 재현율의 균형 지표. 불균형 데이터에서 특히 중요
  • Confusion Matrix — 진양성/위양성/진음성/위음성 각각의 건수 기록
  • Grad-CAM 히트맵 — AI가 이미지의 어느 부분을 보고 판단했는지 시각화

4단계: 통합 대비 산출물

  • 학습된 모델 가중치 파일 (.pth / .h5)
  • 최종 성능 지표 표 (Accuracy, Sensitivity, Specificity, F1, AUROC)
  • Confusion Matrix 시각화 이미지
  • Grad-CAM 예시 이미지 5~10장 (정확한 예측 + 틀린 예측 각각)
  • 전처리 파이프라인 코드 및 설정값 문서
  • 클래스 불균형 처리 방법 및 결과 비교 보고

왜 False Negative가 특히 위험한가요?

False Negative(위음성)은 실제 COVID 양성인데 AI가 "음성"이라고 잘못 판단한 경우입니다. 이 환자는 격리 없이 일반 병동에 입원하게 되어 원내 감염 확산의 원인이 됩니다. 따라서 이 데이터셋에서는 Sensitivity를 최우선으로 높여야 합니다.

의료 AI의 철칙: "놓치느니 한 번 더 의심하는 게 낫다." — 양성을 음성으로 놓치는 것(FN)이 음성을 양성으로 잘못 판단하는 것(FP)보다 훨씬 위험합니다.

EHR(전자건강기록)이란?

EHR은 Electronic Health Record의 약자로, 병원에서 환자에 대해 기록하는 모든 의료 정보를 디지털화한 것입니다. 환자가 언제 입원했는지, 어떤 진단을 받았는지, 혈액검사 결과가 어땠는지, 어떤 약을 처방받았는지 등 병원에서 일어나는 모든 일이 기록됩니다.

비유: 병원판 "블랙박스"라고 생각하면 됩니다. 환자가 병원 문을 들어서는 순간부터 퇴원할 때까지 일어난 모든 의료 행위가 시간순으로 기록된 일기장입니다.

MIMIC-IV란?

MIMIC-IV(Medical Information Mart for Intensive Care IV)는 미국 MIT와 Beth Israel Deaconess Medical Center(BIDMC)가 공동으로 구축한 세계 최대 규모의 공개 임상 데이터베이스입니다. 2008~2019년 사이 BIDMC에 입원한 환자들의 비식별화된 의료 기록이 담겨 있습니다. 연구 목적으로 공개되어 전 세계 의료 AI 연구에 가장 많이 사용되는 데이터셋 중 하나입니다.

비유: 대학병원 10년치 환자 기록을 개인정보만 지우고 통째로 공개한 것. 의료 AI 연구자들에게는 "교과서" 같은 존재입니다.

왜 영상 데이터와 함께 환자 기록이 필요한가요?

실제 의사가 X-Ray를 판독할 때, 사진만 보지 않습니다. "이 환자가 70세 남성이고, 당뇨가 있고, 열이 38.5도이고, 백혈구 수치가 높다"는 정보를 함께 알고 있어야 정확한 진단이 가능합니다. 같은 X-Ray 소견이라도 20대 건강한 환자와 80대 면역저하 환자에서의 의미가 완전히 다르기 때문입니다.

비유: 명탐정이 범죄 현장 사진(영상)만 보는 게 아니라, 피해자의 신원, 목격자 진술, 포렌식 결과(환자 기록)까지 종합해서 사건을 해결하는 것과 같습니다. AI도 마찬가지로, 사진 + 맥락 정보를 함께 보면 훨씬 정확합니다.

CSV.GZ 파일이란?

CSV는 엑셀처럼 행과 열로 된 표 형식의 데이터 파일이고, GZ(gzip)는 파일을 압축한 것입니다. 즉, .csv.gz는 압축된 엑셀 파일이라고 이해하면 됩니다. 용량이 크기 때문에 압축 상태로 저장하며, Python의 pandas 라이브러리는 압축된 채로 바로 읽을 수 있습니다.

비유: 엑셀 파일을 ZIP으로 압축한 것. 다만, Python에서는 압축을 풀지 않고 바로 열 수 있어서 편리합니다.

ANALYSIS GUIDE

개별 분석 시 중점 사항

이 데이터셋을 담당하는 팀원이 통합 전에 반드시 확인하고 도출해야 할 소견들입니다.

1단계: 데이터 품질 점검 (EDA)

  • 각 테이블별 결측값(missing values) 비율 확인 — 특히 labevents, prescriptions 등 대형 테이블에 빈 셀이 얼마나 있는지
  • 각 컬럼의 데이터 타입 확인 — 날짜가 문자열로 저장되어 있진 않은지, 숫자 컬럼에 텍스트가 섞여 있진 않은지
  • 시간 범위(time range) 확인 — 데이터가 실제로 2008~2019년 범위인지, 이상한 미래/과거 날짜가 있진 않은지
  • 환자 수(subject_id) 및 입원 건수(hadm_id) 카운트 — 총 몇 명의 환자, 몇 건의 입원이 있는지
  • 다른 버킷과의 환자 겹침(overlap) 확인 — MIMIC-CXR(버킷 5)과 MIMIC-IV Note(버킷 7)의 subject_id가 얼마나 겹치는지. 이것이 멀티모달 통합의 핵심!
  • 각 사전 테이블(d_로 시작하는 파일)의 코드 커버리지 확인 — 본 테이블의 코드가 사전에 모두 있는지

2단계: 전처리 파이프라인 설계

  • 결측값 처리: 임상적 맥락에 맞게 처리 — 검사를 안 한 것(MNAR)인지, 기록 누락(MAR)인지 구분. 단순 평균 대입은 위험!
  • Feature Engineering: raw 검사값 → 임상적으로 의미있는 피처로 변환 (예: 혈당 수치 → 정상/경계/위험 구간, eGFR 계산, SOFA score 계산)
  • 시계열 정렬(Time-series alignment): 서로 다른 테이블의 이벤트를 시간축으로 정렬 — 입원 시점 기준 상대 시간으로 변환
  • 정규화(Normalization): 검사 수치의 스케일이 항목마다 크게 다르므로 (체온: 36~40, 백혈구: 4,000~11,000) 표준화 필요
  • ICD 코드 그룹핑: 세부 ICD 코드를 상위 카테고리로 묶어 분석 가능한 단위로 축소
  • 중복 레코드 처리: 같은 시점에 같은 검사가 여러 번 기록된 경우의 처리 규칙 정의

3단계: 핵심 지표 도출 (Key Metrics)

  • 환자 인구통계 분포: 연령, 성별, 인종, 보험유형별 분포 — 모델의 편향(bias) 점검에 필수
  • Top 진단 분석: 가장 빈번한 ICD 진단코드 상위 20개 — 프로젝트에서 다룰 주요 질환군 파악
  • 검사값 분포: 주요 lab 항목(CBC, BMP, LFT 등)의 분포 및 이상치(outlier) 비율
  • ICU 사망률(Mortality rate): ICU 입실 환자 중 원내 사망 비율 — 중증도 판단의 기준선
  • 재입원율(Readmission rate): 퇴원 후 30일 내 재입원 비율 — 치료 품질 평가의 핵심 지표
  • 재원일수(Length of Stay): 입원부터 퇴원까지의 평균/중앙값/분포 — 환자 중증도의 간접 지표
  • 시간대별 이벤트 밀도: 입원 후 시간별로 검사/처방/시술이 얼마나 발생하는지 패턴 분석

4단계: 통합 대비 산출물 (Integration Deliverables)

  • Cleaned Feature Matrix: 환자(행) x 피처(열) 형태의 정제된 데이터 테이블. 모델 입력으로 바로 사용 가능한 형태
  • Patient-level Summary Statistics: 환자별 요약 통계 (평균 lab 값, 진단 수, 투약 수, 재원일수 등)
  • Join Keys 문서화: 다른 데이터셋과 연결하는 키 컬럼 정리 — subject_id(환자 고유ID), hadm_id(입원 고유ID), stay_id(ICU 체류 ID)
  • Data Dictionary: 사용한 모든 컬럼에 대한 설명서 (컬럼명, 데이터 타입, 의미, 단위, 결측률 등)
  • 코호트 정의서: 분석 대상 환자군의 포함/제외 기준 문서화 (예: 18세 이상, 흉부 X-Ray 촬영 이력 있는 환자)
  • 전처리 파이프라인 코드: 재현 가능한 형태의 Python 스크립트 (raw → feature matrix 변환 전 과정)
JOIN KEYS

데이터셋 간 연결 키

MIMIC 시리즈 데이터셋(버킷 2, 5, 7)은 공통 키로 연결됩니다. 이 키를 이해하는 것이 멀티모달 통합의 핵심입니다.

subject_id

환자 고유 식별자. 한 환자에게 하나만 부여됩니다. 이 키로 MIMIC-CXR(흉부 X-Ray), MIMIC-IV Note(의사 노트)와 동일 환자를 연결할 수 있습니다.

hadm_id

입원 고유 식별자. 같은 환자가 여러 번 입원하면 각각 다른 hadm_id를 받습니다. 특정 입원 건에 대한 모든 기록을 묶을 때 사용합니다.

stay_id

ICU 체류 식별자. 한 번의 입원 중에도 ICU를 여러 번 들어갈 수 있습니다. ICU 모듈의 데이터를 특정 ICU 체류와 연결할 때 사용합니다.

연결 구조 이해하기

하나의 환자(subject_id)는 여러 번 입원(hadm_id)할 수 있고, 한 번의 입원 중 여러 번 ICU에 입실(stay_id)할 수 있습니다. 이 계층 구조를 이해해야 데이터를 올바르게 결합할 수 있습니다.

비유: 한 사람(subject_id)이 도서관 회원카드 1장을 가지고, 여러 번 방문(hadm_id)하며, 각 방문에서 여러 권의 책(stay_id)을 빌릴 수 있는 것과 같습니다. 1명 → N번 입원 → M번 ICU 입실의 1:N:M 관계입니다.

왜 EHR이 있으면 진단 정확도가 올라가나요?

폐렴이란?

폐렴(Pneumonia)은 폐에 세균이나 바이러스가 침입하여 염증이 생기는 질환입니다. 폐 속의 작은 공기주머니(폐포)에 고름이나 액체가 차면서 호흡이 어려워집니다. 특히 면역력이 약한 어린 아이들에게 치명적일 수 있습니다.

비유: 스펀지(폐)에 물(염증)이 스며든 것. 정상 스펀지는 공기를 잘 흡수하지만, 물에 젖은 스펀지는 공기가 통하지 않아 숨쉬기 어렵습니다.

폐렴이 X-Ray에서 어떻게 보이나요?

정상 폐는 X-Ray에서 까맣게 보입니다 (공기가 많아서). 하지만 폐렴에 걸리면 염증 부위가 하얗게 보입니다 (액체/고름이 차면서 X선을 차단). 이 하얀 부분을 "음영(opacity)" 또는 "경화(consolidation)"라고 부릅니다.

비유: 맑은 유리창(정상 폐)에 하얀 페인트가 뿌려진 것(폐렴). 페인트가 한곳에 집중되면 세균성, 안개처럼 퍼져 있으면 바이러스성입니다.

왜 1~5세 소아 환자인가요?

소아 폐렴은 전 세계 5세 이하 사망 원인 1위입니다. 어린 아이들은 자신의 증상을 정확히 말하기 어렵고, 증상이 급격히 악화될 수 있습니다. 따라서 빠른 영상 진단이 생명을 살리는 핵심 도구가 됩니다. 이 데이터셋은 실제 소아 환자의 X-Ray로 구성되어 있어, 소아 전용 AI 모델 학습에 적합합니다.

비유: 아직 말을 잘 못하는 아기가 아플 때, 의사는 눈에 보이는 단서(X-Ray)에 의존해야 합니다. AI가 그 단서를 빠르게 읽어주는 보조 의사 역할을 하는 것입니다.

세균성 폐렴 vs 바이러스성 폐렴, 뭐가 다른가요?

세균성 폐렴(Bacterial): 특정 부위에 집중적으로 염증이 생깁니다. X-Ray에서 한쪽 폐의 특정 구역이 하얗게 보이는 "엽성 경화(Focal Lobar Consolidation)" 패턴을 보입니다. 항생제 치료가 필요합니다.

바이러스성 폐렴(Viral): 양쪽 폐 전체에 걸쳐 퍼지는 양상입니다. X-Ray에서 "미만성 간질 패턴(Diffuse Interstitial Pattern)"으로 전체적으로 뿌옇게 보입니다. 대증 치료 위주입니다.

비유: 세균성은 벽에 물감을 "한 방울 떨어뜨린 것"(한곳에 집중), 바이러스성은 "스프레이로 뿌린 것"(넓게 퍼짐). 치료법이 다르기 때문에 구분이 중요합니다!

3가지 진단 유형

이 데이터셋의 X-Ray 이미지는 아래 3가지 유형으로 나뉩니다. 폴더는 NORMAL / PNEUMONIA 두 개이지만, PNEUMONIA 내부에서 파일명으로 세균성/바이러스성을 구분할 수 있습니다.

NORMAL 정상

폐가 깨끗하고 투명합니다. 하얀 음영(opacification)이 없으며, 폐의 경계가 선명하게 보입니다. 기관지와 혈관 구조만 정상적으로 관찰됩니다.

BACTERIAL 세균성 폐렴

엽성 경화(Focal Lobar Consolidation) 패턴. 한쪽 폐의 특정 엽(lobe)에 집중된 하얀 음영이 나타납니다. 경계가 비교적 뚜렷하고, 공기기관지조영(air bronchogram)이 보일 수 있습니다.

VIRAL 바이러스성 폐렴

미만성 간질 패턴(Diffuse Interstitial Pattern). 양쪽 폐에 걸쳐 전체적으로 뿌옇게 퍼진 음영이 나타납니다. 경계가 불분명하고, 폐 전체가 "안개 낀 것"처럼 보입니다.

왜 False Negative가 특히 위험한가요?

False Negative(위음성)은 실제 폐렴인데 AI가 "정상"이라고 잘못 판단한 경우입니다. 특히 소아 환자는 증상이 급격히 악화될 수 있어, 폐렴을 놓치면 적절한 치료 시기를 놓쳐 생명이 위험해질 수 있습니다. 따라서 이 데이터셋에서는 Sensitivity를 최우선으로 높여야 합니다.

EASY EXPLANATION

이 데이터셋이 뭔가요?

MRI란 무엇인가요?

MRI(자기공명영상)는 강력한 자석과 전파를 이용해 몸속 사진을 찍는 검사입니다. X-Ray나 CT와 달리 방사선을 사용하지 않아 인체에 무해하고, 뇌처럼 부드러운 조직(연조직)을 매우 선명하게 촬영할 수 있습니다. 촬영 시간은 20~40분 정도 걸리며, 좁은 통 안에 누워 있어야 합니다.

비유: CT가 "몸속을 빠르게 스캔하는 공항 검색대"라면, MRI는 "시간은 더 걸리지만 훨씬 정밀한 고해상도 카메라"입니다. 뇌를 볼 때는 MRI가 압도적으로 좋습니다.

뇌종양이란 무엇인가요?

뇌종양은 뇌 안에 비정상적으로 자라는 세포 덩어리입니다. 정상 세포는 필요한 만큼만 자라고 멈추지만, 종양 세포는 멈추지 않고 계속 자랍니다. 뇌는 딱딱한 두개골로 둘러싸여 있어서 종양이 자라면 뇌를 압박하게 됩니다. 양성(benign)이든 악성(malignant)이든 뇌 안에서 자라면 위험할 수 있습니다.

비유: 뇌를 "꽉 찬 상자"라고 생각하세요. 그 안에 풍선(종양)이 부풀어 오르면, 원래 있던 물건(뇌 조직)이 눌리게 됩니다. 풍선이 클수록, 빨리 자랄수록 위험합니다.

왜 4가지 클래스로 나누나요?

뇌종양이라고 다 같은 게 아닙니다. 종양의 종류에 따라 위험도, 치료 방법, 긴급도가 완전히 다릅니다. 예를 들어 Glioma(신경교종)는 악성이라 즉시 수술해야 하지만, Meningioma(뇌수막종)는 대부분 양성이라 경과 관찰만 할 수도 있습니다. AI가 "종양이 있다/없다"만 구분하면 충분하지 않고, 어떤 종류의 종양인지까지 알려줘야 의사가 올바른 결정을 내릴 수 있습니다.

비유: 소방서에 "불이야!"라고만 신고하면 안 되고, "산불인지, 가스 폭발인지, 전기 화재인지"를 알려줘야 적절한 장비를 가져갈 수 있는 것과 같습니다.

4가지 클래스 쉽게 이해하기

이 데이터셋에는 3가지 종양 유형 + 정상(종양 없음) = 총 4가지 클래스가 있습니다.

1. Glioma (신경교종): 뇌 조직 자체(신경교세포)에서 자라는 종양. 가장 흔하면서도 가장 위험한 원발성 뇌종양입니다. 주변 뇌 조직으로 뿌리를 뻗듯이 침투하기 때문에 깔끔하게 제거하기 어렵습니다. -- 비유: 잔디밭에 퍼진 잡초. 뿌리가 사방으로 뻗어서 뽑기 어렵습니다.
2. Meningioma (뇌수막종): 뇌를 감싸는 얇은 막(수막)에서 자라는 종양. 뇌 조직 밖에서 자라므로 대부분 양성이고, 경계가 뚜렷하여 수술로 깨끗하게 제거할 수 있습니다. -- 비유: 풍선 표면에 붙은 껌. 표면에만 붙어 있어서 떼어내면 풍선(뇌)은 괜찮습니다.
3. No Tumor (정상): 종양이 없는 건강한 뇌 MRI. AI 학습에서 "이것은 정상이다"를 가르치기 위한 대조군(control group)입니다. -- 비유: 시험에서 "틀린 답"만 보여주면 안 되고, "맞는 답"도 함께 보여줘야 구분할 수 있는 것과 같습니다.
4. Pituitary Tumor (뇌하수체 종양): 뇌 밑바닥에 있는 작은 분비샘(뇌하수체)에서 자라는 종양. 대부분 양성이지만 호르몬 분비에 이상을 일으켜 키가 비정상적으로 자라거나, 생리 불순, 시력 저하 등의 증상을 유발합니다. -- 비유: 건물의 "전기 제어실"에 생긴 문제. 건물 자체는 멀쩡하지만 전기(호르몬)가 이상하게 나옵니다.

ANALYSIS GUIDE

개별 분석 시 중점 사항

이 데이터셋을 담당하는 팀원이 통합 전에 반드시 확인하고 도출해야 할 소견들입니다. 4단계로 진행하세요.

1단계: 데이터 품질 점검 (EDA)

  • 이미지 해상도 분포: 모든 이미지가 같은 크기인지 확인. MRI 특성상 다양한 크기가 섞여 있을 수 있음
  • 클래스 균형 확인: no_tumor(395장)가 다른 클래스(~825장)의 절반임을 수치와 그래프로 문서화
  • MRI 촬영 평면 분석: Axial(횡단면) / Sagittal(시상면) / Coronal(관상면) 중 어떤 촬영이 많은지 확인. 클래스별로 촬영 방향이 다를 수 있음
  • 이미지 품질: 노이즈, 아티팩트(artifact), 극단적 밝기/어두움, 잘린 이미지 등 문제 있는 이미지 필터링
  • 중복 이미지 탐지: 해싱(예: perceptual hash)으로 동일/유사 이미지가 Training과 Testing에 겹치지 않는지 확인
  • 채널 수 확인: 그레이스케일(1채널) vs RGB(3채널) 혼재 여부

2단계: 전처리 파이프라인 설계

  • 이미지 리사이징: 모델 입력 크기에 맞춰 통일 (권장: 224x224 또는 256x256). 비율 유지 + 패딩 적용 검토
  • 픽셀 정규화: 0~1 스케일링 또는 ImageNet 평균/표준편차 기반 정규화
  • 데이터 증강 (Augmentation): 특히 no_tumor 클래스에 집중 적용 -- 회전(15도), 좌우 반전, 밝기/대비 변경, Random Crop
  • Validation 세트 생성: Training 2,870장에서 15~20%(~430~570장)를 stratified split으로 분리. 클래스 비율 유지 필수
  • 뇌 영역 크로핑 (Brain Region Cropping): MRI 이미지 주변의 검은 배경을 제거하고 실제 뇌 영역만 추출. 이미지의 약 30~50%가 불필요한 검은 영역일 수 있음
  • 채널 통일: 그레이스케일 이미지는 3채널로 변환 (pretrained 모델 사용 시 필수)

3단계: 모델 학습 및 도출할 핵심 지표

  • Per-class Accuracy: 각 클래스별 정확도. 특히 glioma_tumor 정확도가 가장 중요 (놓치면 생명 위험)
  • Macro F1-Score: 4개 클래스의 F1을 동등하게 평균. 클래스 불균형 상황에서 공정한 평가
  • Weighted F1-Score: 각 클래스의 샘플 수에 비례한 가중 평균 F1
  • Confusion Matrix: 4x4 혼동 행렬. 특히 glioma vs meningioma 오분류에 주목 (MRI 소견이 유사할 수 있음)
  • Top-1 Accuracy: AI의 첫 번째 예측이 맞는 비율
  • Top-2 Accuracy: AI의 상위 2개 예측 안에 정답이 포함되는 비율 (임상에서 "감별진단"에 활용 가능)
  • Per-class Precision & Recall: 특히 glioma의 Recall(재현율)이 가장 중요 -- 악성 종양을 놓치면 안 됨

  • Per-class 성능 표: 각 클래스별 Precision, Recall, F1, Support를 정리한 classification report
  • Confusion Matrix 히트맵: 4x4 행렬을 색상으로 시각화. glioma-meningioma 혼동 영역 강조
  • Grad-CAM 시각화: 각 클래스별 3~5장씩, AI가 뇌의 어느 부분을 보고 판단했는지 히트맵으로 표시
  • 오분류 분석 (Misclassification Analysis): 틀린 예측의 패턴 분석 -- 어떤 클래스가 어떤 클래스로 오분류되는지, 왜 그런지 추론

왜 Glioma Recall이 특히 중요한가요?

Glioma(신경교종)는 이 데이터셋에서 유일한 악성 종양입니다. AI가 Glioma를 다른 클래스로 잘못 분류하면(= False Negative), 환자는 악성 종양인 줄 모르고 적절한 치료 시기를 놓치게 됩니다. 특히 Glioma를 Meningioma(양성)로 오분류하면 "경과 관찰"로 판단해 수술이 지연될 수 있습니다.

의료 AI의 원칙: "악성을 놓치느니, 양성을 한 번 더 검사하는 게 낫다." -- Glioma의 Recall(재현율)을 최우선으로 높여야 합니다. 95% 이상이 목표이며, 이는 glioma 환자 100명 중 95명 이상을 정확히 잡아내야 한다는 뜻입니다.

Top-2 Accuracy가 왜 필요한가요?

실제 임상에서 의사는 "이건 확실히 Glioma다"라고 단정하기보다 "Glioma일 가능성이 높고, Meningioma도 감별해야 한다"처럼 감별진단(Differential Diagnosis) 목록을 세웁니다. AI도 마찬가지로 "1순위 예측 + 2순위 예측"을 함께 제시하면 의사의 의사결정에 더 도움이 됩니다.

비유: 퀴즈에서 "정답은 3번인데 2번도 헷갈린다"고 말할 수 있으면, 선생님이 어디서 혼동하는지 파악해서 더 잘 가르칠 수 있는 것과 같습니다.

EASY EXPLANATION

이 데이터셋이 뭔가요?

MIMIC-CXR-JPG란?

미국 보스턴의 BIDMC(Beth Israel Deaconess Medical Center) 병원에서 실제로 촬영된 흉부 X-Ray 이미지 37만 장입니다. 약 65,000명의 환자에 대해 여러 번 촬영된 이미지들이 포함되어 있으며, 각 이미지에는 14가지 이상의 흉부 질환 라벨이 붙어 있습니다.

비유: 대형 병원의 영상의학과 서버에 저장된 모든 흉부 X-Ray 사진을 연구용으로 공개한 것입니다. 개인정보는 제거(비식별화)되어 있습니다.

데이터셋 1(COVIDx)이나 데이터셋 3(Pneumonia)과 뭐가 다른가요?

COVIDx는 "COVID인지 아닌지"만 판별하는 단순 분류 데이터셋이고, Pneumonia는 "폐렴인지 정상인지"만 봅니다. 둘 다 이미지만 있고, 환자의 다른 정보는 없습니다.

반면 MIMIC-CXR-JPG는:

  • 실제 병원 데이터입니다 (연구용 수집이 아닌 진짜 진료 과정에서 촬영)
  • 같은 환자의 임상 기록(혈압, 혈액검사, 투약 등)에 연결됩니다 (MIMIC-IV)
  • 의사가 작성한 판독 보고서가 있습니다 (MIMIC-IV Note)
  • 14개 이상의 질환을 동시에 다중 라벨로 분류합니다 (한 사진에 폐렴 + 흉수 + 심비대 동시 가능)
비유: COVIDx/Pneumonia는 "시험 문제집"이고, MIMIC-CXR-JPG는 "실제 병원 전자차트 전체"입니다. 문제집은 정답 연습용이고, 전자차트는 실전 AI를 만들 수 있는 진짜 데이터입니다.

왜 이 데이터셋이 프로젝트의 핵심인가요?

우리 프로젝트 "Dr. AI Radiologist"는 멀티모달(다중 정보) AI를 만드는 것이 목표입니다. 의사가 X-Ray만 보고 판단하지 않듯이, AI도 이미지 + 환자정보 + 기존 보고서를 종합해서 판단해야 합니다. 이 세 가지를 모두 연결할 수 있는 데이터셋은 MIMIC 생태계(버킷 2 + 5 + 7)뿐입니다.

핵심: 이 데이터셋은 단독이 아니라 버킷 2(환자 차트) + 버킷 7(의사 소견서)과 합쳐질 때 진정한 가치가 나옵니다. 세 데이터셋의 교차점이 바로 이곳입니다.

ANALYSIS GUIDE

개별 분석 시 중점 사항

이 데이터셋을 담당하는 팀원이 통합 전에 반드시 확인하고 도출해야 할 소견들입니다. 570GB의 크기를 감안해 단계적으로 접근하는 것이 핵심입니다.

1단계: 탐색적 데이터 분석 (EDA)

  • 샘플 이미지 품질 확인: 각 그룹(p10~p19)에서 무작위로 100장씩 뽑아 해상도, 밝기, 대비, 손상 여부 점검
  • 환자당 이미지 수 분포: 어떤 환자는 1장, 어떤 환자는 수십 장일 수 있음. 분포를 히스토그램으로 확인
  • 환자당 스터디 수 분포: 한 환자가 몇 번 병원에 왔는지 (재방문 패턴 파악)
  • MIMIC-IV 연결 검증: subject_id로 버킷 2의 patients.csv와 매칭. 누락 환자 비율 확인
  • MIMIC-IV Note 연결 검증: subject_id로 버킷 7의 radiology 보고서와 매칭. 보고서 없는 이미지 비율 확인
  • 촬영 유형(View) 분포: PA(후전면) / AP(전후면) / Lateral(측면) 비율 확인. PA가 가장 표준적이므로 우선 사용
  • 그룹별 데이터량: p10~p19 각 그룹의 환자 수와 이미지 수가 균등한지 확인

2단계: 전처리 파이프라인 설계

  • 대표 서브셋 우선 구성: 전체 570GB가 아닌 p10 그룹만 먼저 처리 (약 57GB, 전체의 ~10%)
  • 이미지 크기 표준화: 다양한 해상도를 모델 입력 크기(224x224, 512x512 등)로 통일
  • 품질 필터링: 너무 어두운/밝은 이미지, 잘린 이미지, 회전된 이미지 제거
  • 환자 단위 Train/Val/Test 분리: 같은 환자가 다른 세트에 들어가지 않도록 patient-level split 필수
  • CLAHE(대비 향상): 흉부 X-Ray의 폐 영역 가시성을 높이는 히스토그램 균등화 적용
  • 메타데이터 테이블 생성: (subject_id, study_id, dicom_id, view_type, linked_to_mimic4, linked_to_note) 매핑 CSV

3단계: 핵심 성능 지표

  • Multi-label Classification Metrics: 하나의 이미지에 여러 질환이 동시에 있으므로 각 질환별로 따로 평가해야 합니다
  • Mean AUROC across Pathologies: 14개 질환 각각의 AUROC를 구한 후 평균. 이것이 CXR 분류의 표준 지표입니다
  • Per-pathology AUROC: 질환별 성능을 개별 확인 (어떤 질환을 잘 맞히고 어떤 것을 못 맞히는지)
  • Image-Text Alignment Score: 버킷 7의 판독 보고서와 결합 시, 이미지와 텍스트 임베딩의 유사도 측정
  • Multi-label F1 (Macro/Micro): 전체 질환에 대한 종합 F1 점수
  • Linkage Coverage Rate: 전체 이미지 중 MIMIC-IV + MIMIC-IV Note와 모두 연결 가능한 비율

4단계: 통합 대비 산출물

  • 샘플링 전략 문서: 570GB에서 어떤 기준으로 서브셋을 선별했는지 근거와 절차 기록
  • 전처리된 서브셋: 표준화된 크기, 품질 필터링 완료된 이미지 세트 + 메타데이터 CSV
  • 연결 검증 보고서: 버킷 2, 7과의 subject_id 매칭률, 누락 데이터 분석 결과
  • 서브셋 기반 베이스라인 모델: p10 그룹으로 학습한 multi-label 분류 모델 (DenseNet121 또는 ResNet50 등)
  • 질환별 성능 표: 14개 질환 각각의 AUROC, F1, Precision, Recall
  • Grad-CAM 시각화: AI가 X-Ray의 어느 부분을 보고 각 질환을 판단했는지 5~10장 예시

왜 Mean AUROC가 핵심 지표인가요?

흉부 X-Ray 분류에서는 Accuracy(정확도)를 쓰면 안 됩니다. 대부분의 질환은 "없는" 경우가 훨씬 많기 때문에 (예: 기흉은 전체의 5% 미만), "전부 없다"고 예측해도 95% 정확도가 나옵니다. AUROC는 이런 불균형에 영향을 받지 않으며, 각 질환을 실제로 잘 구분하는지 측정합니다.

참고: CheXpert, MIMIC-CXR 관련 논문들의 표준 벤치마크가 Mean AUROC입니다. 0.85 이상이면 실용적 수준으로 평가됩니다.

EASY EXPLANATION

이 데이터셋이 뭔가요?

NDC 코드란?

NDC(National Drug Code)는 미국에서 모든 의약품에 부여하는 고유 식별 번호입니다. 이 코드 하나로 약의 성분, 함량, 제형(알약/캡슐/액체), 제조사까지 정확히 특정할 수 있습니다. 예를 들어 같은 이부프로펜 200mg이라도 제조사가 다르면 NDC 코드가 다릅니다.

쉽게 말하면: 약의 바코드 같은 것입니다. 마트에서 바코드를 찍으면 어떤 상품인지 정확히 나오듯, NDC 코드를 알면 어떤 약인지 100% 특정됩니다.

이미지는 어떻게 촬영된 건가요?

미시간 대학교 약국에서 로봇 카메라 시스템이 약병(medication bottle) 안에 담긴 알약을 위에서 아래로(top-down view) 촬영합니다. 실제 약국 조제 과정에서 촬영된 이미지이므로, 알약이 겹쳐 있거나 방향이 제각각인 현실적인 상황이 반영되어 있습니다.

쉽게 말하면: 약통 뚜껑을 열고 위에서 사진을 찍은 것입니다. 약국에서 약을 조제한 뒤 "이 약이 맞나?" 확인하는 용도로 촬영된 실제 현장 사진입니다.

왜 알약 식별이 중요한가요?

미국에서만 매년 수천 명이 투약 오류(medication error)로 사망합니다. 약사가 처방전에 적힌 약 대신 비슷하게 생긴 다른 약을 조제하는 실수가 대표적입니다. AI가 조제된 알약 이미지를 자동으로 확인하면, 잘못된 약이 환자에게 전달되기 전에 차단할 수 있습니다.

쉽게 말하면: "처방전에는 A약이 적혀 있는데, 약통에 들어 있는 건 정말 A약이 맞나?"를 AI가 사진을 보고 확인해주는 것입니다. 사람 눈보다 빠르고 정확한 더블체크 시스템입니다.

ANALYSIS GUIDE

개별 분석 시 중점 사항

이 데이터셋을 담당하는 팀원이 통합 전에 반드시 확인하고 도출해야 할 소견들입니다.

1단계: 데이터 품질 점검 (EDA)

  • NDC별 이미지 수 분포 확인 — 20개 클래스가 균등한지, 불균형이 있는지 히스토그램으로 시각화
  • 이미지 품질/크기 분산 확인 — 해상도가 일정한지, 특정 NDC만 해상도가 다른지 체크
  • 외형 유사 NDC 쌍 식별 — 같은 제조사 코드(앞 5자리)를 공유하는 NDC끼리 이미지를 나란히 비교하여, 모델이 혼동할 가능성이 높은 쌍을 미리 파악
  • 이미지 밝기, 대비, 색상 분포 통계 — 배치(batch)별로 촬영 환경이 달랐는지 확인
  • 손상되거나 비어 있는 이미지 파일이 없는지 무결성 검증

2단계: 전처리 파이프라인 설계

  • 배경 제거(Background Subtraction): 약병 내부 배경을 제거하고 알약 영역만 추출. 약병 색상이 다양할 수 있으므로 적응형 임계값 적용
  • 색상 정규화(Color Normalization): 조명 차이에 의한 색감 변동을 최소화. 알약의 색상이 중요한 특징이므로 과도한 정규화는 주의
  • 리사이징: 모델 입력 크기에 맞춰 통일 (예: 224x224). 비율 유지 후 패딩 또는 Center Crop
  • 데이터 증강(Augmentation): 회전(rotation)이 특히 중요 — 약병 안에서 알약 방향이 제각각이므로. 좌우/상하 반전, 랜덤 밝기/대비 변경, 경미한 색조(hue) 변경
  • 주의: 색상 기반 증강은 조심해야 함 — 알약의 색상 자체가 분류의 핵심 단서이므로 과도한 색상 왜곡은 오히려 성능을 떨어뜨림

3단계: 모델 학습 및 도출할 핵심 지표

  • Top-1 Accuracy — 모델이 1순위로 예측한 NDC가 정답인 비율. 목표: 95% 이상
  • Top-3 Accuracy — 상위 3개 예측 안에 정답이 포함된 비율. 안전망 역할, 목표: 99% 이상
  • Per-class Precision & Recall — 20개 NDC 각각의 정밀도/재현율. 특정 NDC만 성능이 낮은지 확인
  • Confusion Matrix — 20x20 혼동 행렬. 특히 어떤 NDC 쌍이 서로 혼동되는지 집중 분석
  • Macro F1-Score — 20개 클래스의 F1을 동일 가중치로 평균. 소수 클래스의 성능도 반영
  • 학습 곡선(Loss/Accuracy curve) — 과적합 여부 확인

4단계: 통합 대비 산출물

  • 학습된 모델 가중치 파일 (.pth / .h5)
  • NDC별 성능 테이블 — 20개 클래스 각각의 Precision, Recall, F1, Support(이미지 수)
  • Confusion Matrix 히트맵 — 20x20 시각화, 혼동이 큰 셀을 강조 표시
  • Most-Confused Pairs 분석 — 가장 많이 혼동되는 NDC 쌍 Top-5와 해당 이미지 예시
  • 전처리 파이프라인 코드 및 설정값 문서
  • 처방 검증 연동 API 스펙 — 알약 이미지를 입력하면 NDC 코드 + 신뢰도를 반환하는 API. 소견서 시스템 및 약국 시스템과 연동하기 위한 인터페이스 정의

왜 "Critical Drug Mix-up 0건"이 절대 목표인가요?

외형이 비슷한 약물(Look-Alike Drugs)을 혼동하는 것은 단순한 분류 오류가 아니라 환자의 생명에 직결되는 위험입니다. 예를 들어 혈압약 대신 당뇨약이 투여되면 저혈당 쇼크가 올 수 있습니다. 따라서 모델 성능 평가 시 단순 정확도뿐 아니라, 임상적으로 위험한 약물 쌍 간의 혼동이 0건인지를 별도로 검증해야 합니다.

의료 AI의 철칙: "비슷하게 생긴 약은 가장 위험한 적이다." — Look-Alike Drug 쌍에 대한 혼동률이 0%에 수렴해야 안전하게 배포할 수 있습니다.

1) AI 추론 단계: radiology.csv의 영상 판독 보고서는 AI가 흉부 X-Ray를 이해하는 데 필요한 학습 라벨/맥락 정보를 제공합니다. 의사가 쓴 판독문("소견: 우측 하엽에 경화 소견...")을 AI가 학습하여, 영상에서 무엇을 봐야 하는지 배웁니다.

2) 소견서 자동 작성 단계: discharge.csv의 퇴원 기록은 AI가 최종적으로 생성해야 할 문서의 형식입니다. AI는 이 방대한 퇴원 기록을 학습하여, 의사처럼 자연스러운 임상 보고서를 작성하는 법을 배웁니다.

RAG(검색 증강 생성) 연결: 이 텍스트 데이터는 프로젝트의 RAG 시스템에서 지식 베이스(Knowledge Base) 역할을 합니다. AI가 새로운 영상을 분석할 때, 유사한 과거 판독 보고서를 벡터 DB에서 검색하여 참고하면서 더 정확하고 근거 있는 소견서를 작성합니다. 마치 경험 많은 의사가 비슷한 케이스를 떠올리며 진단하는 것과 같습니다.

EASY EXPLANATION

이 데이터셋이 뭔가요?

퇴원 기록(Discharge Summary)이란?

환자가 병원에서 퇴원할 때 담당 의사가 작성하는 종합 퇴원 기록입니다. 입원 이유, 검사 결과, 치료 내용, 처방약, 퇴원 후 주의사항 등 입원 기간 동안 일어난 모든 것이 담겨 있습니다. 보통 수천 단어에 달하는 긴 문서입니다.

비유: 여행 다녀온 후 쓰는 "여행 보고서"와 같습니다. 왜 갔는지(입원 이유), 어디를 갔는지(진단), 뭘 했는지(치료), 뭘 샀는지(처방약), 다음에 또 가야 하는지(퇴원 후 계획)를 전부 정리한 종합 보고서입니다.

영상 판독 보고서(Radiology Report)란?

영상의학과 전문의가 X-Ray, CT, MRI 등 의료 영상을 보고 작성하는 분석 보고서입니다. 일반적으로 세 가지 핵심 섹션으로 구성됩니다:

Indication (촬영 이유) — "기침과 발열 지속, 흉부 X-Ray 촬영"

Findings (소견) — "우측 하엽에 간유리 음영(GGO) 관찰됨. 심장 크기 정상."

Impression (결론) — "폐렴 의심. 추적 검사 권고."

비유: 자동차 정비소에서 차를 점검한 후 주는 "정비 소견서"와 같습니다. 왜 맡겼는지(Indication), 어디가 문제인지(Findings), 최종 판단과 다음 조치(Impression)를 적어줍니다.

텍스트 데이터가 AI에게 왜 중요한가요?

우리 프로젝트의 AI는 영상을 분석하는 것만으로는 부족합니다. 최종적으로 의사가 읽을 수 있는 보고서를 자동으로 작성해야 합니다. 그러려면 AI가 "의사의 언어"를 먼저 배워야 합니다. 수십만 건의 실제 판독 보고서와 퇴원 기록을 학습하면, AI는 의학 용어, 문장 구조, 보고서 형식을 자연스럽게 익히게 됩니다.

비유: 외국어를 배울 때 원어민이 쓴 글을 많이 읽는 것과 같습니다. AI도 의사들이 실제로 쓴 보고서를 대량으로 읽으면서 "의료 글쓰기"를 배웁니다. 많이 읽을수록 더 자연스러운 보고서를 쓸 수 있습니다.

NLP(자연어 처리)란?

Natural Language Processing의 약자로, 컴퓨터가 사람의 언어(자연어)를 이해하고 생성하는 기술입니다. 우리가 일상적으로 쓰는 ChatGPT, 번역기, 맞춤법 검사기 모두 NLP 기술입니다. 이 프로젝트에서는 의료 텍스트에 특화된 NLP를 사용합니다.

비유: 외국인 친구에게 한국어를 가르치는 것과 비슷합니다. 단어 뜻(토큰화), 문법(구문 분석), 맥락 파악(의미 분석)을 단계별로 가르치듯이, 컴퓨터에게도 의학 언어를 단계별로 가르칩니다. 일반 한국어와 의학 용어가 다르듯, 일반 NLP와 의료 NLP도 다릅니다.

비유: 형사가 사건을 해결할 때 CCTV 영상(이미지) + 지문 데이터(수치) + 목격자 진술(텍스트)을 모두 종합하는 것처럼, 우리 AI도 영상 + 수치 + 텍스트를 결합해야 정확한 진단을 내릴 수 있습니다.

ANALYSIS GUIDE

개별 분석 시 중점 사항

이 데이터셋을 담당하는 팀원이 통합 전에 반드시 수행해야 할 4단계 분석입니다.

1단계: 탐색적 데이터 분석 (EDA)

  • 레코드 수 파악: discharge.csv, radiology.csv 각각의 총 행 수 확인 — 몇 건의 퇴원 기록, 몇 건의 판독 보고서가 있는지 기본 규모 파악
  • 텍스트 길이 분포: text 컬럼의 문자 수/단어 수 분포를 히스토그램으로 시각화 (퇴원 기록은 수천 단어, 판독문은 수백 단어 예상)
  • 빈 값/NULL 텍스트 확인: text 컬럼이 비어 있거나 NULL인 행이 있는지 점검 — 이런 행은 학습에 사용 불가하므로 규모를 파악
  • 보고서 구조 섹션 식별: radiology.csv의 보고서에서 Indication / Findings / Impression 등의 섹션 헤더가 얼마나 일관되게 나타나는지 확인
  • subject_id 중복 확인 (MIMIC-CXR 연계): MIMIC-CXR(버킷 5)과 subject_id가 얼마나 겹치는지 확인 — 이 겹치는 환자가 Image-Text Pair의 후보
  • 시간 분포: chartdate/charttime 기준으로 데이터가 어떤 기간에 걸쳐 분포하는지 확인

2단계: 전처리 파이프라인 설계

  • 텍스트 클리닝: 불필요한 아티팩트 제거 (서식 태그, 반복 공백/줄바꿈, 특수문자 노이즈), 줄바꿈 표준화, 인코딩 이슈 해결
  • 섹션 추출 (Section Extraction): 판독 보고서를 Indication / Findings / Impression으로 구조적으로 분리 — 정규표현식 또는 규칙 기반 파서 설계
  • 토큰화 (Tokenization): 의료 텍스트에 적합한 토크나이저 선정 (BioBERT, ClinicalBERT, PubMedBERT 등의 토크나이저 비교 실험)
  • Train/Val/Test 분할: subject_id 기준으로 환자 단위 분할 (같은 환자의 기록이 Train과 Test에 동시에 들어가면 data leakage 발생)
  • 비식별화 검증: MIMIC은 이미 비식별 처리되어 있지만, 혹시 남아 있는 개인정보(이름, 날짜, 병원 이름 등)가 있는지 샘플링하여 검증

3단계: 핵심 지표 및 중간 산출물

  • 어휘 분석 (Vocabulary Analysis): 의료 용어 빈도수 분석 — 가장 많이 등장하는 질병명, 약물명, 해부학 용어 목록 도출. WordCloud 시각화 권장
  • 보고서 섹션 추출 정확도: 섹션 파서가 Indication/Findings/Impression을 올바르게 분리하는 비율 측정 (랜덤 100건 수동 검증 권장)
  • Text-Image 매칭률: radiology.csv의 레코드 중 MIMIC-CXR(버킷 5)의 이미지와 subject_id로 매칭되는 비율 확인 — 이것이 VLM 학습 데이터의 규모를 결정
  • 개체명 인식 (Named Entity Recognition) 결과: 텍스트에서 질병명, 약물명, 수치(혈압, 체온, 산소포화도 등)를 자동 추출한 결과물
  • 문장 수준 임베딩: RAG 지식 베이스용 sentence embedding 벡터 생성 (BioSentVec, ClinicalBERT 등 의료 특화 모델 사용)

4단계: 통합 대비 산출물

  • 클리닝 완료된 텍스트 코퍼스 (discharge_cleaned.csv, radiology_cleaned.csv)
  • 섹션 추출 완료된 판독 보고서 (radiology_sectioned.csv — Indication, Findings, Impression 각각 별도 컬럼)
  • Text-Image 페어 인덱스 파일 (subject_id + radiology note_id + CXR image_id 매핑 테이블)
  • 의료 개체명 인식(Medical NER) 결과 파일 (질병, 약물, 측정값 태그가 달린 데이터)
  • RAG용 임베딩 벡터 파일 (.npy 또는 FAISS 인덱스 형태)
  • 전처리 파이프라인 코드 및 설정값 문서
  • EDA 결과 보고서 (텍스트 길이 분포, 어휘 분석, 섹션 분포 시각화)

BLEU와 ROUGE가 뭔가요?

BLEU는 AI가 생성한 텍스트가 정답 텍스트와 얼마나 단어 수준에서 겹치는지 측정합니다. ROUGE는 정답 텍스트의 핵심 내용을 AI가 얼마나 빠짐없이 포함했는지 측정합니다. 두 지표 모두 0~1 사이 값으로, 1에 가까울수록 좋습니다.

비유: BLEU는 "AI가 쓴 답안에 정답 키워드가 얼마나 있나" (정밀도 관점), ROUGE는 "정답 키워드를 AI가 얼마나 빠뜨리지 않았나" (재현율 관점)입니다. 시험 채점할 때 핵심 키워드 포함 여부로 점수를 매기는 것과 비슷합니다.

NER F1-Score는 뭔가요?

NER(Named Entity Recognition)은 텍스트에서 의미 있는 개체(질병명, 약물명, 수치 등)를 자동으로 찾아내는 기술입니다. F1-Score는 "찾아야 할 것을 얼마나 잘 찾았는지"와 "잘못 찾은 것은 없는지"의 균형 점수입니다.

비유: 보물찾기에서 F1-Score는 "진짜 보물을 얼마나 많이 찾았나" + "돌멩이를 보물이라고 잘못 가져온 건 없나"를 종합한 점수입니다. 둘 다 잘해야 높은 점수가 나옵니다.
